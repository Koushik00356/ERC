What this demonstrates

The agent holds a key. Prompt injection means that key now answers to whoever wrote the text the agent read — a webpage, an email, a tool result. No filter catches every injection, so the wallet is built on the assumption that the agent is already compromised.

The agent can only call propose(). It cannot add, remove or reconfigure a rule, and it cannot clear a latched breaker. Those require the owner key, which the agent never holds. Containment is therefore a property of the key separation, not of the agent's judgement.

The metric is realised adversarial loss — value that actually left the wallet — rather than a refusal count. A configuration that refuses 53 of 55 proposals and loses the balance anyway has contained nothing, and a refusal-rate metric would score it well.

Where this is weak

Stated here rather than discovered in review.

The allowlist result depends on the threat model. The adversary here has one destination and it is not listed. An attacker who redirects value to a listed payee walks straight through.

Timelock defers, it does not refuse. Its zero loss is "nothing settled yet", not containment. Its real contribution is review time, and there is no reviewer in this demo.

This is not an EntryPoint deployment. Proposals go through a direct path, so gas figures are relative policy costs, not bundler-accepted validation gas.
